## 1. 背景与目标

### 1.1 背景

二手家具流通的核心矛盾是「非标大件」：**定价难、信任难、配送难**。三件事任意一件没解决，交易就走不完。

同时，家具是典型的高隐含碳商品——一件布艺沙发的全生命周期碳排放可达数十至上百千克 CO₂e，其中绝大部分在生产环节。**延长一件家具的使用寿命，是最直接的减碳手段**，这构成了平台「低碳」价值主张的物理基础，而不只是营销话术。

### 1.2 产品定位

**同城二手家具交易与回收平台**：卖家 3 分钟完成发布，买家 2 分钟完成下单，配送可预约到具体时段。

### 1.3 MVP 目标（上线后 4 周口径）

| 指标 | 目标值 | 说明 |
| --- | --- | --- |
| 有效在售 SKU | ≥ 100 | 审核通过且未下架 |
| 发布 → 审核通过率 | ≥ 60% | 反映发帖规范引导是否有效 |
| 详情页 → 下单转化 | ≥ 8% | 核心漏斗 |
| 下单 → 支付转化 | ≥ 50% | 低于此值说明运费/时效劝退 |
| 支付 → 完成物流预约 | ≥ 80% | 低于此值说明运力或时段供给不足 |
| 订单履约完成率 | ≥ 70% | 支付后 14 天内完成收货 |

### 1.4 本期范围

**In Scope（本期做）**

| 模块 | 包含能力 |

| 能力 | 原因 | 预留方式 |

### 1.5 关键决策（需评审拍板）

| 编号 | 决策点 | 选项 | 建议 | 影响 |
| --- | --- | --- | --- | --- |
| D1 | 本期如何承接「回收」 | A 完全不做　B 轻表单：发布页增加「申请回收」入口，提交后运营线下电话报价、上门搬运、线下成交　C 完整线上回收单 | **B** | 保留核心业务叙事，但避免在 MVP 引入报价引擎和逆向物流 |
| D2 | 是否做担保交易 | A 直接打款给卖家　B 平台代收，确认收货后结算 | **B** | 无担保则纠纷率不可控，是二手平台生死线 |
| D3 | 物流运力来源 | A 自建　B 第三方同城货运（货拉拉/快狗）API 下单　C 卖家自行配送 | **B + C 兜底** | 自建成本过高；纯卖家配送时效不可控 |
| D4 | 平台服务费 | A 0　B 向买家收 5%　C 向卖家收 5% | **B，订单页明示** | 首期可用 0 费率换增长，但价格结构必须预留 |
| D5 | 端形态 | A 纯 H5　B 小程序　C App | **H5 优先，小程序二期** | 二手交易强依赖微信分享，小程序是终局 |

## 2. 用户与角色

| 角色 | 描述 | 核心目标 | 关键痛点 | 本期权限 |
| --- | --- | --- | --- | --- |
| 卖家（个人） | 处理闲置家具的 C 端用户 | 快速卖掉、卖个合理价 | 不知道定多少钱、搬不动、怕被砍价骚扰 | 发布、编辑、下架、接单、确认自提 |
| 回收提交者 | 有旧家具需要清走的用户 | 有人上门搬走，最好还能给点钱 | 找人搬运比卖更麻烦 | 提交回收申请、查看进度 |
| 买家 | 想低价买家具的个人 | 便宜、成色真实、能送到家 | 怕货不对板、怕运费刺客、怕放不下 | 搜索、筛选、下单、支付、预约物流、退款 |
| 运营 | 平台内容与履约管理者 | 保证商品质量与履约时效 | 审核量大、纠纷判责难 | 商品审核、订单干预、退款审批、运力调度 |
| 管理员 | 系统配置者 | 配置分类、运费规则、费率 | — | 全量权限、参数配置 |

**核心用户假设（需在灰度中验证）**
- 买家最敏感的是「总价（含运费）」而非商品单价；
- 卖家最愿意付出的是「拍照上传」，最不愿意填的是「尺寸」——因此尺寸必须给默认值或可跳过；
- 回收提交者的第一诉求是「省事」，第二诉求才是「卖钱」。

## 4. 核心业务主流程

### 4.1 主链路

```
卖家发布商品
   ↓ 填写信息 + 上传图片 + 定价 + 设置交易方式
提交审核 ──(驳回)──→ 修改后重新提交
   ↓ (通过，≤2h)
商品上架（在售）
   ↓
买家搜索 / 分类浏览 → 商品详情
   ↓
点击「立即购买」→ 订单确认页
   ↓ 选择：同城自提 / 平台配送 → 计算运费
提交订单 → 待支付（30 分钟倒计时）
   ↓ 支付成功
待预约物流 ──→ 选择配送日期与时段 ──→ 已预约
   ↓
配送中 → 已送达
   ↓ 买家确认收货（或 T+3 自动确认）
已完成 → T+1 结算给卖家
```

### 4.2 异常分支

| 分支 | 触发 | 处理 |
| --- | --- | --- |
| 超时未支付 | 30 分钟 | 订单自动关闭，商品回到在售，释放库存占用 |
| 卖家未确认自提 | 24 小时 | 提醒卖家；48 小时未响应可无责取消 |
| 买家申请退款 | 发货前 | 全额退款，商品回到在售 |
| 商品被他人买走 | 并发下单 | 下单即锁定 30 分钟，其余用户提示「已被预订」 |
| 商品审核驳回 | 违规/信息不全 | 站内通知 + 驳回原因 + 一键修改 |
| 配送失败 | 买家不在/地址错 | 改约 1 次；二次失败订单关闭并按规则退款（扣运费） |

## 5. 模块一：商品发布（M1）

### 5.1 目标

让一个不会写文案的用户，**在 3 分钟内、不填任何非必填项**也能发出一个合格商品。

### 5.2 发布流程（分步，共 3 步）

| 步骤 | 内容 | 可跳过 |
| --- | --- | --- |
| Step 1 照片 | 上传 1–9 张图，首图为主图；提供拍摄引导（全景 + 瑕疵特写 + 尺寸参照物） | 否（至少 1 张） |
| Step 2 信息 | 品类（三级）、标题、成色、描述；尺寸/材质/风格/品牌为选填 | 否（品类+标题+成色必填） |
| Step 3 交易 | 价格、交易方式（自提/配送/皆可）、所在区域 | 否 |
| 提交 | 预览 → 提交审核 | — |

> 设计原则：**选填项折叠**。Step 2 默认只展示 4 个必填项，其余收进「补充信息（可提升成交率）」折叠区。

### 5.3 字段清单

| # | 字段 | 类型 | 必填 | 校验规则 | 说明 |
| --- | --- | --- | --- | --- | --- |
| 1 | 商品图片 | 图片数组 | 是 | 1–9 张；jpg/png/webp；单张 ≤5MB；自动压缩至长边 1080px | 首图为列表封面；第 2 张起建议瑕疵特写；检测纯色/模糊图并提示 |
| 2 | 一级品类 | 枚举 | 是 | 见附录 A | 选择后联动二级 |
| 3 | 二级品类 | 枚举 | 是 | 必须属于所选一级 | — |
| 4 | 三级品类 | 枚举 | 否 | 必须属于所选二级 | 无三级时隐藏 |
| 5 | 商品标题 | 文本 | 是 | 5–30 字；禁含手机号/微信号/二维码/外链 | 提供「品牌 + 品类 + 特征」模板提示 |
| 6 | 成色 | 枚举 | 是 | 5 档，见附录 A | 影响搜索筛选与价格建议 |
| 7 | 商品描述 | 多行文本 | 否 | 0–500 字；敏感词过滤 | 为空时用模板生成（品类+成色+尺寸） |
| 8 | 尺寸（长/宽/高） | 数字×3 | 否 | 1–500cm，整数 | 留空提示「填写尺寸可提升约 30% 成交」；提供常见品类默认值 |
| 9 | 材质 | 枚举 | 否 | 见附录 A | — |
| 10 | 风格 | 枚举 | 否 | 见附录 A | — |
| 11 | 品牌 | 文本 | 否 | ≤20 字 | 用于搜索命中 |
| 12 | 价格 | 金额 | 是 | 1–99999 元，最多两位小数 | 一物一价，数量固定为 1 |
| 13 | 参考价提示 | 系统计算 | — | 同城同二级品类近 30 天成交中位数 | 仅提示，不强制 |
| 14 | 交易方式 | 多选 | 是 | 同城自提 / 平台配送 | 至少选 1 项 |
| 15 | 所在区域 | 级联选择 | 是 | 城市-区-街道 | 用于距离计算；仅展示到区级 |
| 16 | 详细地址 | 文本 | 否 | ≤100 字 | 不在商品页公开，仅下单后对买家可见 |
| 17 | 卖家联系方式 | 继承账号 | 是 | — | 商品页脱敏展示（虚拟号/站内信） |
| 18 | 是否申请回收 | 开关 | 否 | D1 选 B 时展示 | 开启后走回收轻表单，不生成商品 |

### 5.4 关键业务规则

| 编号 | 规则 |
| --- | --- |
| R1 | **一物一价**：本期不做库存与数量，每件商品唯一。售出后自动转为「已售出」，不可再次购买 |
| R2 | **草稿保留 7 天**：未提交的草稿存本地 + 服务端，7 天后清理 |
| R3 | **审核 SLA 2 小时**（9:00–21:00 人工在岗；其余时段次日上午处理） |
| R4 | **机审前置**：图片鉴黄/鉴暴、标题敏感词、盗图感知哈希去重，命中直接驳回或转人工 |
| R5 | **价格异常拦截**：低于同品类中位数 10% 时二次确认（防误填、防钓鱼） |
| R6 | **编辑限制**：在售状态可编辑；已被下单（待支付/待发货）时仅可降价，不可改图改描述 |
| R7 | **联系方式保护**：商品页不展示真实手机号，统一走平台虚拟号或站内留言 |
| R8 | **驳回必须给原因**：从固定原因字典中选择 + 补充说明，支持一键修改重提 |

### 5.5 商品状态机

| 状态 | 编码 | 可流转至 | 触发 |
| --- | --- | --- | --- |
| 草稿 | `DRAFT` | 审核中 | 用户保存草稿 |
| 审核中 | `PENDING` | 在售 / 已驳回 | 提交 / 审核完成 |
| 已驳回 | `REJECTED` | 审核中 | 用户修改后重提 |
| 在售 | `ON_SALE` | 已预订 / 已下架 / 已售出 | 被下单 / 卖家下架 / 成交 |
| 已预订 | `RESERVED` | 在售 / 已售出 | 支付超时 / 支付成功 |
| 已售出 | `SOLD` | — | 订单完成 |
| 已下架 | `OFF_SHELF` | 在售 | 卖家操作或超 90 天未成交自动下架 |
| 违规下架 | `BANNED` | — | 运营处理 |

### 5.6 验收标准

| 编号 | 场景 | 预期结果 |
| --- | --- | --- |
| AC-1 | 只上传 1 张图，其余选填全空 | 可成功提交并进入审核 |
| AC-2 | 标题含手机号 | 提交时拦截，提示「请勿填写联系方式」 |
| AC-3 | 上传第 10 张图 | 按钮置灰，提示最多 9 张 |
| AC-4 | 填写价格 5 元（远低于中位数） | 弹二次确认 |
| AC-5 | 审核驳回 | 用户收到通知，进入编辑页可见驳回原因 |
| AC-6 | 商品在售时被下单 | 列表页显示「已被预订」，其他人不可下单 |
| AC-7 | 草稿放置 8 天后打开 | 草稿已清理，提示重新发布 |

## 6. 模块二：搜索与分类（M2）

### 6.1 目标

让买家**在 3 次点击内**到达一个可能购买的商品详情页。

### 6.2 分类体系（三级）

| 一级 | 二级示例 | 三级示例 |
| --- | --- | --- |
| 沙发座椅 | 三人沙发、双人沙发、单人沙发、沙发床、懒人沙发 | 布艺 / 皮质 / 实木框架 |
| 床与床垫 | 双人床、单人床、床垫、上下铺、榻榻米 | 1.5m / 1.8m / 2.0m |
| 桌几 | 餐桌、书桌、茶几、边几、梳妆台 | 圆形 / 方形 / 可折叠 |
| 柜类收纳 | 衣柜、书柜、电视柜、鞋柜、斗柜 | 推拉门 / 平开门 |
| 椅凳 | 餐椅、办公椅、吧台凳、长凳 | — |
| 办公家具 | 工位、会议桌、文件柜 | — |
| 其他 | 户外家具、儿童家具、装饰家具 | — |

> 分类设计原则：**一级按品类**（用户认知最直接），**二级按形态/尺寸**（决定能否放得下），**三级按材质**（决定价格带）。空间维度（客厅/卧室）放到筛选器而非分类树。

### 6.3 首页（P01）

- 顶部：搜索框（点击进入搜索页）+ 定位城市
- 金刚区：8 个一级分类图标入口
- 运营位：Banner 1 个（本期可静态）
- 推荐流：默认「综合排序」，无限滚动，每页 20 条

### 6.4 搜索结果页（P03）

**搜索交互**

| 能力 | 规则 |
| --- | --- |
| 输入联想 | 输入 ≥2 字触发，返回最多 10 条：品类词 > 品牌词 > 风格词，按热度排序 |
| 搜索命中 | 标题、描述、品牌、品类名；分词后 AND 匹配，支持同义词（如「沙发」≈「sofa」） |
| 历史记录 | 本地保存最近 10 条，可单条删除 / 清空 |
| 热搜词 | 运营配置 Top 10，每日更新 |
| 空结果 | 展示「未找到相关商品」+ 放宽筛选建议 + 同城同类推荐 6 条 |

**筛选维度（可多选组合）**

| 筛选 | 选项 | 说明 |
| --- | --- | --- |
| 价格区间 | 自定义 min–max + 快捷档（0–200 / 200–500 / 500–1000 / 1000+） | 按商品价，不含运费 |
| 成色 | 5 档多选 | — |
| 距离 | 1km / 3km / 5km / 10km / 全城 | 需用户授权定位，未授权则隐藏 |
| 交易方式 | 支持自提 / 支持配送 | — |
| 材质 | 枚举多选 | — |
| 风格 | 枚举多选 | — |
| 尺寸 | 长/宽/高 上限输入 | 解决「放不下」痛点 |

**排序规则**

| 排序 | 权重构成 |
| --- | --- |
| 综合（默认） | 图片质量 30% + 新鲜度 30% + 卖家历史表现 20% + 价格竞争力 20% |
| 最新发布 | 按 `created_at` 倒序 |
| 价格从低到高 / 从高到低 | 按 `price` 排序 |

## 7. 模块三：下单支付 + 物流预约（M3）

### 7.1 订单价格构成

```
应付总额 = 商品价 + 配送费 + 楼层搬运费 + 拆装费 + 平台服务费 − 优惠金额
```

| 项 | 收取方 | 说明 |
| --- | --- | --- |
| 商品价 | 卖家 | 商品标价 |
| 配送费 | 运力方 | 自提为 0 |
| 楼层搬运费 | 运力方 | 无电梯且 ≥2 楼时收取 |
| 拆装费 | 运力方 | 床/衣柜等需拆装品类 |
| 平台服务费 | 平台 | 建议 5%，订单页逐项明示，禁止隐藏 |
| 优惠金额 | — | 本期为 0，字段预留 |

**运费计价规则（可配置）**

| 项 | 规则 |
| --- | --- |
| 起步价 | 首 3 公里 30 元 |
| 里程费 | 超出 3 公里部分 2 元/公里 |
| 体积档 | 小件 <0.3m³：0 元；中件 0.3–1m³：30 元；大件 1–3m³：80 元；超大 >3m³：150 元 |
| 楼层费 | 无电梯时，2 楼起每层 10 元/件，单件封顶 50 元；有电梯 0 元 |
| 拆装费 | 床 100 元、衣柜 120 元、沙发 50 元，其余 0 元 |
| 搬运距离费 | 车辆停放点距门栋 >20 米时，每 10 米加 5 元（封顶 30 元） |
| 计价时点 | 订单确认页计算并锁定；预约改期不重算；改地址需重新计算并二次确认 |

### 7.2 下单流程与校验

| 步骤 | 页面 | 校验 |
| --- | --- | --- |
| 1 | 点击「立即购买」 | 未登录 → 登录；商品非在售 → 拦截提示 |
| 2 | 订单确认页 | 选收货/自提地址；选物流方式；展示费用明细；同意《交易服务协议》 |
| 3 | 提交订单 | 服务端二次校验库存锁（`RESERVED`），锁定 30 分钟 |
| 4 | 收银台 | 30 分钟倒计时；超时自动关闭 |
| 5 | 支付成功 | 订单转「待预约物流」；商品转「已售出」 |
| 6 | 预约物流 | 选择日期与时段，提交后转「已预约」 |

**下单校验清单**
- 商品状态必须为 `ON_SALE`
- 不能购买自己发布的商品
- 收货地址必须在本市服务范围内（超出则仅支持自提）
- 自提方式下不计算运费，但必须选择自提时间

### 7.3 物流方式

| 方式 | 费用 | 流程 | 适用 |
| --- | --- | --- | --- |
| 同城自提 | 0 | 买家约时间 → 卖家确认 → 线下交接 → 买家确认收货 | 小件、买家有车 |
| 平台配送 | 按 7.1 计价 | 买家预约时段 → 平台派单第三方运力 → 配送 → 送达确认 | 大件主力方式 |

**配送预约规则**

| 项 | 规则 |
| --- | --- |
| 可约日期 | T+1 至 T+7（T 为支付日） |
| 可约时段 | 09:00–12:00 / 12:00–15:00 / 15:00–18:00 / 18:00–21:00 |
| 改约 | 每个订单免费 1 次；第 2 次起收 20 元改约费；配送当日不可改 |
| 取消 | 配送前 24 小时可免费取消并全额退款；24 小时内取消扣除配送费 |
| 运力上限 | 单时段容量可配置，满额则时段置灰 |
| 送达确认 | 运力端上传签收照片；买家 72 小时未确认则自动确认收货 |

### 7.4 支付

| 项 | 规则 |
| --- | --- |
| 渠道 | 微信支付（JSAPI/H5）、支付宝（WAP） |
| 支付超时 | 30 分钟，超时关闭订单并释放商品 |
| 资金流向 | 平台商户号代收 → 确认收货后 T+1 结算至卖家（担保交易，决策 D2） |
| 退款 | 仅支持「发货前全额退款」，原路退回，1–3 个工作日到账 |
| 对账 | 每日 T+1 生成对账文件，差异告警 |

### 7.5 订单状态机

| 状态 | 编码 | 可流转至 | 触发方 |
| --- | --- | --- | --- |
| 待支付 | `PENDING_PAYMENT` | 待预约物流 / 已关闭 | 买家支付 / 超时 |
| 待预约物流 | `PENDING_SCHEDULE` | 已预约 / 退款中 | 买家预约 / 申请退款 |
| 已预约 | `SCHEDULED` | 配送中 / 退款中 | 运力接单 |
| 配送中 | `DELIVERING` | 已送达 | 运力出发 |
| 已送达 | `DELIVERED` | 已完成 | 买家确认 / 72h 自动 |
| 已完成 | `COMPLETED` | 退款中（售后） | 系统 |
| 已关闭 | `CLOSED` | — | 超时未支付 |
| 退款中 | `REFUNDING` | 已退款 | 买家申请 |
| 已退款 | `REFUNDED` | — | 平台审批通过 |

> 状态流转全部写入 `order_status_logs`，用于纠纷判责。

### 7.6 售后最小集

本期只做三件事，其余转人工：

1. **发货前全额退款**（自动通过）
2. **改约物流时间**（自动，规则见 7.3）
3. **货不对板投诉**（转人工工单，48 小时内响应，平台先行判定，支持部分退款）

### 7.7 验收标准

| 编号 | 场景 | 预期结果 |
| --- | --- | --- |
| AC-14 | 选择配送，地址 8 公里外，无电梯 5 楼，买床 | 费用明细各项正确展示，合计无误 |
| AC-15 | 提交订单后不支付 | 30 分钟后订单关闭，商品恢复在售 |
| AC-16 | 两人同时下单同一商品 | 仅一人成功，另一人提示「已被预订」 |

## 12. 风险与开放问题

| 编号 | 风险 | 影响 | 应对 |
| --- | --- | --- | --- |
| RK1 | 同城运力不足或拒单 | 配送履约失败 | 双供应商 + 卖家自送兜底 + 时段容量控制 |

1. 回收（D1）本期是否真的只做轻表单？若要做线上报价，需追加 2 周。
2. 服务费向谁收、收多少，需与财务确认资金流与开票。
3. 是否需要企业/商家入驻（B 端供给）？若需要，发布模块要加资质审核。
